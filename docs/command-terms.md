# Command terms

The first word of an exam question tells you how much to write and what shape
the answer takes. Most marks lost on content he actually knew are lost here:
a correct, well-written *description* scores nothing against a question that
said *explain*.

Learn these as instructions, not vocabulary.

## The ones that decide your mark

| Term | What the examiner wants | Typical failure |
| --- | --- | --- |
| **State** | One fact or answer. No reasoning. | Writing a paragraph and losing time you needed elsewhere |
| **List** | Several items, no detail, no sentences needed | Explaining each one |
| **Outline** | A brief account — the main points, no depth | Going too deep, or too shallow to show the points are distinct |
| **Describe** | What happens, in order. No causes. | Explaining why, which isn’t asked for |
| **Explain** | **Why** or **how** — the mechanism and the causes | Describing what happens. This is the single most expensive mistake |
| **Distinguish** | Differences, stated **against** each other | Two separate descriptions in two paragraphs |
| **Compare** | Similarities **and** differences, comparatively | A list of facts about each thing separately |
| **Compare and contrast** | The same, with both explicitly covered | Giving only differences |
| **Discuss** | A balanced account — more than one side, then a view | Arguing one side only |
| **Evaluate** | Strengths **and** weaknesses, then a judgement | Describing without judging |
| **Suggest** | A plausible answer for a novel situation | Refusing to answer because you weren’t taught this exact case |
| **Deduce** | A conclusion that follows from given information | Answering from memory instead of from the data in front of you |
| **Predict** | The expected result, from the given trend or principle | Explaining instead of stating the outcome |
| **Justify** | Reasons or evidence supporting a conclusion | Restating the conclusion |
| **Annotate** | Add brief notes to a diagram | Labelling only |
| **Label** | Add names to a diagram | Adding explanation nobody asked for |
| **Calculate** | A numerical answer — **show the working, give the unit** | Dropping the unit, which is its own mark |

## Two rules that carry most of the value

**Describe versus explain.** Describe is *what*. Explain is *why* or *how*. If a
question says explain and your answer contains no "because", no "due to", and no
mechanism, you’ve almost certainly written a description and will score close
to nothing regardless of accuracy.

**Compare and distinguish need comparative sentences.** Not "water is dense.
Air isn’t dense." Instead: "Water is denser than air, so it provides greater
buoyancy." Every sentence should contain both sides, or a word like *whereas*,
*while*, or *than*.

## Marks tell you the length

The mark allocation is an instruction about how many distinct points to make.

- **[1]** — one point. One sentence.
- **[2–3]** — two or three separate, creditable points.
- **[4–6]** — a structured answer. Plan it for fifteen seconds first.
- **[7+]** — extended response. Structure it, and use the links between topics;
  that’s what the extra marks are for.

Each marking point normally needs to be *separate*. Saying the same thing twice
in different words scores once. Running out of things to say at [5] usually
means the question wanted links to another topic.

## Before you write anything

1. **Underline the command term.** Every time.
2. **Look at the marks.** That’s how many points you need.
3. **Check whether the question names a specific example**, a named organism,
   or a data set. If it does, an answer that doesn’t use it’s capped.
